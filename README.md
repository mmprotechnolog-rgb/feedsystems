# feedsystems.ru — страница-заглушка

Статическая страница «Сайт находится в разработке» для домена **feedsystems.ru**.
Чистые HTML5 + CSS3: без фреймворков, без JavaScript, без внешних CDN, без счётчиков и сторонних скриптов.
Все ресурсы (шрифт, логотип, фон, иконки) лежат внутри проекта.

## 1. Какие файлы загрузить на хостинг

Загрузите **всё содержимое папки `feedsystems/`** (не саму папку) в корневой каталог сайта на хостинге —
обычно он называется `public_html`, `www`, `htdocs` или `feedsystems.ru/public_html`.

После загрузки в корне сайта должны лежать `index.html`, `.htaccess`, `favicon.ico` и папки `css`, `assets`, `fonts`.

* `.htaccess` начинается с точки и в некоторых FTP-клиентах и файловых менеджерах скрыт — включите отображение скрытых файлов и убедитесь, что он загружен.
* `README.md` загружать не обязательно.
* Сохраняйте структуру папок: все пути в коде относительные (`css/style.css`, `assets/logo.svg` и т. д.).

## 2. Как привязать домен feedsystems.ru

Конкретные DNS-записи и IP-адрес выдаёт хостинг — здесь они намеренно не указаны.

1. В панели хостинга добавьте сайт/домен `feedsystems.ru` и укажите для него каталог, куда загружены файлы. Добавьте также `www.feedsystems.ru` как алиас (синоним) того же сайта — это нужно для редиректа и SSL-сертификата.
2. У регистратора домена сделайте **одно** из двух (как рекомендует хостинг):
   * **либо** укажите NS-серверы хостинга;
   * **либо** оставьте DNS у регистратора и создайте записи, которые даст хостинг: обычно `A` (и при наличии `AAAA`) для `feedsystems.ru` и `A`/`CNAME` для `www`.
3. Подождите обновления DNS (от нескольких минут до 24–48 часов). Проверить можно командой `nslookup feedsystems.ru` или сервисом проверки DNS.

## 3. Как настроить HTTPS

1. В панели хостинга выпустите SSL-сертификат для **обоих** имён: `feedsystems.ru` и `www.feedsystems.ru`. Почти все хостинги дают бесплатный сертификат Let's Encrypt одной кнопкой («SSL», «Сертификаты», «Let's Encrypt»).
2. Сертификат выпускается только после того, как DNS уже указывает на хостинг (пункт 2).
3. Перенаправление `http → https` уже прописано в `.htaccess`. Если в панели есть галочка «Перенаправлять на HTTPS» — можно включить и её, конфликта не будет.
4. Когда убедитесь, что HTTPS работает стабильно, можно включить HSTS — раскомментируйте строку `Strict-Transport-Security` в `.htaccess`.

## 4. Как настроить перенаправление с www

**Apache (большинство виртуальных хостингов).** Ничего делать не нужно: `.htaccess` уже отправляет постоянный редирект 301
`http(s)://www.feedsystems.ru/...` → `https://feedsystems.ru/...` и `http://feedsystems.ru/...` → `https://feedsystems.ru/...`.
Если редиректы не срабатывают — уточните в поддержке хостинга, включён ли `mod_rewrite` и разрешены ли `.htaccess` (`AllowOverride All`).

**Nginx (VPS или хостинг без Apache).** `.htaccess` там не работает. Пример конфигурации (пути к сертификатам и каталогу подставьте свои):

```nginx
# http → https, www → без www
server {
    listen 80;
    listen [::]:80;
    server_name feedsystems.ru www.feedsystems.ru;
    return 301 https://feedsystems.ru$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;
    server_name www.feedsystems.ru;
    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;
    return 301 https://feedsystems.ru$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;
    server_name feedsystems.ru;
    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    root /var/www/feedsystems;
    index index.html;
    charset utf-8;

    location / {
        try_files $uri $uri/ =404;
    }

    location ~* \.(webp|svg|png|ico|woff2)$ {
        expires 30d;
        add_header Cache-Control "public";
    }

    location ~* \.css$ {
        expires 7d;
    }

    location ~ /\. {
        deny all;
    }
}
```

Если в панели хостинга есть отдельная настройка «Основной домен / редирект с www» — достаточно выбрать там `feedsystems.ru` как основной.

## 5. Как проверить работу сайта

1. Откройте в браузере все четыре варианта — каждый должен привести на `https://feedsystems.ru/` с замочком в адресной строке:
   * `http://feedsystems.ru`
   * `http://www.feedsystems.ru`
   * `https://www.feedsystems.ru`
   * `https://feedsystems.ru`
2. Проверьте коды ответа из терминала:
   ```
   curl -I http://www.feedsystems.ru      # ожидается 301, Location: https://feedsystems.ru/
   curl -I https://www.feedsystems.ru     # ожидается 301, Location: https://feedsystems.ru/
   curl -I http://feedsystems.ru          # ожидается 301, Location: https://feedsystems.ru/
   curl -I https://feedsystems.ru         # ожидается 200
   ```
3. Убедитесь, что загрузились логотип, фон и иконка во вкладке. В DevTools браузера (F12 → Network) не должно быть ошибок 404.
4. Нажмите кнопку «Связаться с нами» — откроется `https://protechnolog.ru/contact/`.
   На телефоне нажмите номер — должен предложиться звонок; e-mail — открыться почтовая программа.
5. Проверьте телефон в портретной и альбомной ориентации и ПК. Горизонтальной прокрутки быть не должно.
6. Проверьте сертификат: например, на ssllabs.com/ssltest.

## 6. Как заменить заглушку полноценным сайтом

1. **Запрет индексации.** Сейчас в `index.html` стоит
   ```html
   <!-- ЗАГЛУШКА: удалите эту строку после запуска полноценного сайта, чтобы разрешить индексацию -->
   <meta name="robots" content="noindex, follow">
   ```
   Это просит поисковики не индексировать заглушку. `robots.txt` при этом специально **разрешает** обход сайта — иначе поисковик не увидит сам `noindex`.
   В новом сайте этого тега быть не должно (если новый сайт выкладывается поверх заглушки, просто удалите строку вместе с комментарием).
2. **Замена файлов.** Удалите файлы заглушки (`index.html`, `css/`, `assets/`, `fonts/`, иконки) и загрузите новый сайт в тот же каталог,
   либо переключите корневой каталог домена в панели хостинга на папку нового сайта.
3. **`.htaccess`.** Правила HTTPS и редиректа с www стоит сохранить. Если новый сайт приходит со своим `.htaccess` (например, CMS) — перенесите в него блок `RewriteRule` для www и https из текущего файла.
4. **Canonical.** В новом сайте у каждой страницы должен быть свой `<link rel="canonical">`; у главной — `https://feedsystems.ru/`.
5. После запуска добавьте сайт в Яндекс Вебмастер и Google Search Console и отправьте главную страницу на переобход.

## Технические заметки

* Шрифт — Manrope (вариативный, 200–800), подключён локально, только кириллица и латиница (~40 КБ).
* Фон подгружается через `<picture>`: телефоны в портретной ориентации получают вертикальный кадр (~33 КБ), ноутбуки — 1280 px (~49 КБ), большие экраны — 1920 px (~80 КБ).
* С исходного кадра удалена надпись телеканала в правом верхнем углу.
* Затемнение — CSS-градиенты поверх фото: на ПК плотнее слева под текстом, на телефонах равномерное. Контраст белого текста с фоном на всех проверенных разрешениях — не ниже 7:1 (WCAG AAA).
* Учтены вырезы экрана iPhone (`safe-area-inset`).
* Проверенные разрешения: 320×568, 375×812, 390×844, 430×932, 844×390 (альбомная), 1280×720, 1440×900, 1920×1080.
